---
title: Agentic Mode
description: Automate applications with natural language using Alumnium's agentic MCP tools.
---

Agentic mode lets your coding agent delegate automation goals to Alumnium. Alumnium uses an LLM to interpret commands, choose actions, verify application state, and retrieve data. This allows to significantly reduce the context usage of the coding agent at the cost of slower execution.

## Setup

Agentic mode is the default. Follow the [setup instructions](/docs/mcp/overview#setup) and configure an [AI provider](/docs/getting-started/configuration).

Test runners can set `ALUMNIUM_MCP_REQUIRE_STEP=true` when starting `alumnium mcp`
to require a nonnegative integer `step` on every
`do` and `check` call, plus a positive integer `attempt` on every `do` call.
Use `attempt: 1` for a new action and `2` and up for retries of that action;
`check` does not require an attempt. Use `step: 0` for setup before the first written step. Invalid or
missing labels are rejected before any browser action or check runs, so the agent
can retry with the correct parameter. Labels remain optional by default. This
validates the label's presence and format, not whether it names the correct step.

## Tools

In agentic mode, the MCP Server exposes Alumnium's core automation capabilities:

| Tool                                | Description                                                                 |
| ----------------------------------- | --------------------------------------------------------------------------- |
| [`start`](/docs/mcp/overview#start) | Initialize browser/mobile session                                           |
| [`stop`](/docs/mcp/overview#stop)   | Stop session and retrieve token usage statistics                            |
| `do`                                | Execute natural language automation commands with optional vision support   |
| `check`                             | Verify statements about the current page state with optional vision support |
| `get`                               | Extract data from pages using natural language descriptions                 |
| `learn`                             | Teach how to handle instructions that `do`, `check` or `get` got wrong      |
| `forget`                            | Forget a lesson taught with `learn` that turned out wrong                   |
| `wait`                              | Wait a fixed duration or until a natural language condition is met          |
| `fetch_accessibility_tree`          | Debug page structure with raw accessibility tree                            |

### `do`

Perform [actions][6] in the application using natural language commands and return summary of the performed steps. Alumnium automatically captures screenshot upon completion and stores it in the artifacts directory.

Set `vision` to `true` when choosing an action requires visual information, such as distinguishing icon controls with identical accessible names. Alumnium supplies the current screenshot and accessibility tree to its action agent. It still interacts through element IDs. The option defaults to `false`.

### `check`

[Verify][7] application state and run assertions using natural language commands. Returns the result of the check along with explanation the verification was evaluated. Alumnium automatically captures screenshot upon completion and stores it in the artifacts directory.

### `get`

[Extract][8] data from the application based on natural language descriptions. If data is not found, returns explanation why it can't be retrieved. Alumnium automatically captures screenshot upon completion and stores it in the artifacts directory.

### `learn`

Teach Alumnium how to handle an instruction after `do`, `get` or `check` handled it incorrectly. Pass `kind` (`do`, `get` or `check`), the `instruction` in the same format as passed to that tool, and either:

- `actions` for `do`: the [steps][14] that achieve the goal;
- `hint` for `get` and `check`: where to [look for data][15] or what makes a [statement true][16].

The lesson applies to the rest of the session. Set [`ALUMNIUM_KNOWLEDGE`][17] to `true` to persist it in the `.alumnium/knowledge` directory of the MCP server, so it also applies to later sessions and test runs. Pass `layer` to choose where: `product` (default) for every platform of the app, `web`, `ios` or `android` for one platform, or `shared` for every app. Set `knowledge` in `alumnium:options` of `start` to persist lessons in a named [knowledge scope][18].

### `forget`

Forget a lesson taught with `learn`. Pass the `kind`, the `instruction` exactly as taught, and the `layer` it was taught in (`product` by default). Returns whether a lesson was forgotten.

### `wait`

Wait for a fixed duration or until a natural language condition is met. Pass a number (1–30) to wait that many seconds, or a string condition (e.g. `"user is logged in"`) to poll with AI-powered verification until it becomes true or a timeout is reached.

### `fetch_accessibility_tree`

Returns the raw accessibility tree of the current page as XML. Useful for debugging when `do`, `check`, or `get` behave unexpectedly — inspect the tree to verify element visibility, roles, and attributes.
